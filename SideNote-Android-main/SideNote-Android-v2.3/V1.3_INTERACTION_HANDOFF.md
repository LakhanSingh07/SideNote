# SideNote v1.3 — Overlay interaction safety pass

Scope: modified original v1.2 source, *not* a verified Android build.

## Changes
- Floating-card editor Done, Back arrow, and hardware Back now return to the original card rather than opening the sidebar (if the editor was launched from a card).
- Card content refreshes from the saved record after editor close while preserving position and minimized state.
- During service destruction, prevent asynchronous floating-card recreation and remove pending handlers before overlay cleanup.
- Theme refresh and asynchronous floating card restoration bail out if service shutdown has started or overlay permissions are revoked.
- Edge tab explicitly exposes a click action to Android accessibility services.

## Acceptance required in Antigravity
1. Compile on Android SDK with Gradle, address any diagnostics.
2. Float note A, Edit, change title/body, Done: same window stays at same position with new text; no sidebar opens.
3. Repeat test with editor Back arrow and Android Back. Verify no draft loss.
4. Edit via sidebar: Done returns to sidebar.
5. Float 2 notes, change theme, both restore in original positions; no duplicate windows.
6. Stop overlay service while editor is open, assert no overlay recreated and no crashes.
7. Revoke overlay permission and ensure no crash/reappearing overlay.
8. Samsung/OnePlus/Pixel: unlock, rotate, keyboard input, process kill, aggressive battery optimization.
9. TalkBack focus and activation on edge handle, close and minimize controls.

Known gaps: build and real-device tests not executed here. Source still lacks full approved visual fidelity, spring-motion suite and app-wide automation coverage. Existing notes store uses SharedPreferences rather than a production database and should be load-tested.
