# SideNote v1.0 source-finalization pass

## Changes made to v0.9
- Dedicated drag grip on every floating card. Header action buttons now have separate touch targets and should not compete with card dragging.
- Floating cards have a guarded six-card limit rather than silently generating unlimited overlays.
- Appearance selection can refresh existing floating card views without restarting the service. It preserves card positions and minimized state, but hides any open sidebar/editor after safely flushing the draft.
- `Ui.configure()` runs before new sidebar/editor/card views to use current theme preference.
- Card entrance animation uses a short overshoot interpolator; sidebar enters from the active edge.
- Long note view explicitly scrolls. Cleans pending UI handler tasks when overlay service stops.
- Version bumped to 1.0.0-source; **this is not a production version declaration**.

## Known issues / not completed
- No Android compile/test performed; must fix discovered compiler errors before production use.
- No screenshots or measured pixel fidelity, no real keyboard/IME behavior test.
- No independently verified protected-screen behavior, lifecycle resilience, or OEM background restrictions.
- Multi-card state is memory-resident: Android killing the service dismisses overlays, though note data stays locally saved.
- Not all interactions from the 12-screen aspirational mockup have been implemented.
- No signed APK, AAB, store verification, or accessibility audit.

## Antigravity acceptance sequence
1. Build debug on JDK 17 and SDK 35; fix any compilation failures.
2. Install on real Android 13/14/15+ phones; grant overlay/notification permissions.
3. Open six independent cards; drag each by grip; edit, minimize, restore, close; verify action taps don't start drag.
4. Check save under rapid typing, force-stop, and keyboard open/close; record actual losses.
5. Change light/dark/system mode with cards open, verify positions and appearance.
6. Lock/unlock repeatedly; handle display rotate and font scale >= 1.3.
7. Test reminders, import/export, share-to-note, and notification flow.
8. Capture screenshots and compare every approved UX screen; fix remaining deltas.
9. Run lint, instrumented tests and release QA before claiming production readiness.
