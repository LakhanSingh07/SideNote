# SideNote v1.4 — Floating Card Controls

Based on v1.3 source. No compilation or runtime tests have been performed.

## Source changes
- Every expanded floating note now has a card-size control (compact / regular / tall) with independently persisted choices per note ID.
- Every expanded floating note has a 100% / 85% / 75% transparency control, persisted per note ID.
- Card dimensions are bounded to the available display metrics, and moving/resizing uses the existing position clamps.
- Restore/recreate preserves per-card visual preferences.
- Card entrance scales and fades with a short overshoot easing.

## Important boundaries
- The size control is a three-step preset, not freeform drag-to-resize.
- Floating card position is retained during in-session resizing, but positions are not persisted across process death.
- Animations are interpolator-based; this is not an Android physics spring engine.
- Android overlays can be hidden by sensitive apps or terminated by device-specific restrictions.
- Approved multi-screen visual concept is not yet pixel-perfect implemented.
- These changes are NOT verified by Gradle, instrumentation or real device tests.

## Antigravity verification gates
1. Run `./gradlew :app:assembleDebug` with the configured SDK.
2. Fix any compile failures; do not mark code verified before an actual successful build.
3. Create two notes and float both. Cycle each through all three sizes and opacities; verify independent saved settings.
4. Confirm cards remain in view on small displays, rotate device, and repeat.
5. Confirm Edit, minimize, restore, close and drag remain usable at narrow sizes.
6. Test system font scaling, keyboard, screen lock/unlock, service restart and overlays blocked by sensitive apps.
7. Audit accessibility touch-target size and color contrast. The compact control row may require responsive layout work.
