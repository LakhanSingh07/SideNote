# SideNote Windows v0.8.1 — security and sync audit

## Changed
- Validate incoming upsert payload and delete payload *before* storing any divergent change in `sync_conflicts`. Invalid imported mutations abort the SQLite transaction.

## Critical blockers (NOT resolved)
1. Sync exports only the first 500 local changes (`export_bundle(..., 0)`), with no per-peer cursor or pagination. Histories greater than 500 changes will never fully transfer.
2. Pairing uses manually shared 256-bit symmetric key. This is experimental trust bootstrap, not a production pairing protocol; key rotation and revocation are absent.
3. Ciphertext authentication is present but explicit session identity, anti-replay policy, peer-bound acknowledgements and recovery procedures need design and tests.
4. Listener binds on all network interfaces and can be exposed to unwanted private networks. Add interface selection, firewall guidance, connection rate limits and peer authorization before release.
5. Windows Rust compilation, actual local-network transfer and Android compatibility tests NOT run in this environment.

## Required next implementation
- Per-peer sync cursors, bounded paging, and acknowledgement after durable imports; repeated sync eventually converges for >1000 changes.
- Device-specific identity keys; mutual pairing approval, key derivation/rotation and revocation.
- Replay protections, strict size/time limits and negative-security tests.
- Two-instance Windows test, then Android Kotlin protocol integration and migration tests.

## Acceptance gate
Do not call this encrypted transport production-ready until wrong-key, replay, deletion, conflict, 1500-change convergence, reconnect and interruption tests pass.
