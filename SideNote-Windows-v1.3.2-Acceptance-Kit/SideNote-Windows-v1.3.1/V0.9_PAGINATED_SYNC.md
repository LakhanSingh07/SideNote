# SideNote Windows v0.9 — Paginated LAN sync source (unverified)

## Implemented
- Persistent per-peer inbound cursors in `sync_peer_cursors` (new SQLite table, additive migration).
- Authenticated encrypted Hello/round-trip page exchange uses the pre-existing shared XChaCha20 key.
- Repeated 500-record export/import pages until both sides return an empty page.
- Each peer cursor advances only after a page import commits. Replaying a page after interruption is idempotent using `imported_changes`.
- Strict peer/device identity checks for each bundle.
- Sequential remote revisions can update a note originally imported from the same peer; edits made locally are preserved as conflicts.
- Source safety checks are performed, **not** Rust compilation or two-PC runtime validation.

## Unresolved security and correctness gates
1. Shared-key approach is not a complete interactive verified-device pairing protocol. Secret provisioning, per-peer identity binding, key rotation, revocation and discovery remain incomplete.
2. The server currently binds `0.0.0.0:43861` and accepts peers holding the shared key; require explicit user consent, firewall policy, bind restrictions and pairing review before shipping.
3. Imported changes are not re-broadcast to a third peer: this is a direct two-device prototype, not multi-device mesh sync.
4. Conflict detection is origin-based rather than a full causal revision graph. Multiple offline edits, especially delete/update races, need extensive test coverage.
5. Current database size limits and 5 MB encrypted packets may reject extremely large bundles: implement byte-aware batching and backpressure.
6. Same-network devices need manual IP. Reconnect, mDNS and background retry are unimplemented.
7. Windows build, migration, two-device 1,500+ edit roundtrip, wrong-key rejection, and interrupted transfer need real tests.
8. Android sync module and compatible protocol are **not implemented**.

## Recommended acceptance sequence
1. Compile Windows Tauri/Rust source and resolve errors.
2. Test two isolated SQLite profiles with distinct installation IDs, with 1,500+ updates in each direction and last-write snapshots.
3. Drop connection mid-transfer and ensure replay does not duplicate writes.
4. Test conflicting offline edits and delete/update races.
5. Test wrong-key, malformed payload, mismatched device ID and public-IP rejection.
6. Do not deploy or market as secure automatic sync until these gates pass.
