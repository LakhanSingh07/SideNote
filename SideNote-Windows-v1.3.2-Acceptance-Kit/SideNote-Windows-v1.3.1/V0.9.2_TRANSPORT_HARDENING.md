# SideNote Windows v0.9.2 — Bounded LAN sync sessions

## Changes
- Cap a single TCP sync exchange at 1024 pages rather than 10000.
- Reject a client or server session after three consecutive pages with no acknowledgement/received-cursor progress.
- Preserve the pre-existing persisted cursor and transactional import semantics.
- Add source-level regression check for the session limit relationship.

## Known blockers
- Actual Rust/Tauri compile and Windows two-machine runtime tests have NOT run here.
- Shared-secret pairing does not constitute per-device identity approval or revocation.
- Background reconnection, discovery, QR and Android interoperability are absent.
- 1024 pages is a safety cap, not a promise of complete synchronization for arbitrarily large histories; reconnect to continue large backlogs.
- Current sync service is still experimental. Do not ship for handling sensitive notes until independently security-reviewed.

## Antigravity acceptance
1. Install dependencies and run cargo test / cargo check and npm build.
2. Connect two Windows devices and verify 1500+ changes in both directions.
3. Test interrupted transfer, 3 repeated empty/no-progress pages, invalid key, wrong device, malformed page, and reconnect.
4. Confirm data is not lost or duplicated and retained conflicts can be resolved.
5. Verify application UI, floating windows, tray and keyboard shortcuts.
