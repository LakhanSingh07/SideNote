# SideNote Windows — Device Identity Foundation (source only)

## What changed
- Added `src-tauri/src/device_identity.rs` with Ed25519 key generation, public-key encoding, challenge signing and signature verification.
- Challenge proof domain-separates SideNote auth and binds both participant public keys to the signed nonce.
- Added four Rust unit test cases (valid signature, wrong peer, different challenge, malformed signature). Tests are written but not executed here.

## NOT IMPLEMENTED — security blockers
- No persistent private-key storage or OS protection (Windows DPAPI/credential vault).
- No transport handshake integration: the experimental shared-key protocol is **unchanged**.
- No authenticated key agreement/session-key derivation (e.g. vetted Noise framework or TLS mutual auth).
- No first-use public-key fingerprint comparison / QR mutual approval.
- No peer-key trust store, rotation, revocation or active-session invalidation.
- No protection against an attacker who obtains the existing shared LAN key.
- No end-to-end compiled Windows build or two-computer tests.

## Required before enabling public sync
1. Decide on a reviewed protocol (Noise XX/IK or TLS mutual auth), binding peer identity into the transcript and deriving fresh session keys. Do not invent custom encryption handshake.
2. Generate/store device signing credentials in OS-protected storage, with secure migration/backup policy.
3. Require explicit mutual approval with fingerprint/short authentication string; reject unauthorised peers by default.
4. Persist approved *public keys* (not editable UUIDs), implement unpair/revoke and terminate old sessions.
5. Only then wire signatures and the authenticated session keys into the LAN transport and delete shared-key trust code.
6. Compile/test against two Windows installations; test MITM attempts, spoofed UUID, wrong keys, repeated sessions, reconnect, and 1500+ changes.
7. Extend the *same specified protocol* to Android, using Android Keystore and corresponding verified primitives.
