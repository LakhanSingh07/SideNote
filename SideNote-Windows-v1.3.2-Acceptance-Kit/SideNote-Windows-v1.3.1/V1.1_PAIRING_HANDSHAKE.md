# SideNote Windows v1.1 — authenticated LAN handshake (source candidate)

## Changes
- Unique persistent Ed25519 identity seed created for each existing/new Windows installation.
- Public-key display in Trusted Devices.
- Trusted peer entry requires verified 32-byte public key (64 hexadecimal characters) in addition to UUID.
- Both sides challenge each other with fresh 32-byte random nonces before exchanging changes.
- Each signed proof binds signer public key, recipient public key and challenge nonce.
- Rejects mismatched pinned keys, wrong recipient signatures and unpaired legacy UUID-only devices.
- Existing shared-key XChaCha20-Poly1305 transport remains in use; this adds peer proof, NOT a redesigned key exchange.

## SECURITY GATES — NOT PRODUCTION READY
- The Ed25519 secret seed is stored in local SQLite sync_meta without Windows DPAPI protection. Migrate to OS-protected private-key storage before shipping sync.
- Pinning is MANUAL. User must verify exchanged 64-character public key using a trustworthy independent channel. Malicious initial pairing otherwise remains possible.
- The existing shared secret is still required and must be exchanged securely. Rotation/revocation is manual.
- LAN network listener, auth transcript, and end-to-end tests remain unverified. Peer verification does not prove transport is immune to every active-attack scenario.
- Device IDs and public keys must be migrated carefully when upgrading from pre-v1.1 trusted devices.
- Neither Rust `cargo check/test` nor actual Windows two-PC sync was executed here because Rust toolchain is unavailable.

## Acceptance to perform in Antigravity
1. On Windows `cargo check`, `cargo test`, `npm install`, `npm run build`, `npm run tauri build` (fix any failures).
2. Open two PCs: copy each device UUID and public key and add the other under Trusted Devices; verify exchanged keys through separate channel.
3. Configure same LAN shared secret; sync 1 note both directions.
4. Wrong peer key must fail before importing any data.
5. Missing peer key (legacy allowlist) must fail closed.
6. Tamper with a challenge/signature: connection rejected without importing changes.
7. Repeat after restart: identity public key remains stable.
8. Remove a paired device and rotate shared secret. Removed peer must fail.
9. Test two-way 1,500+ edits, disconnect/reconnect, conflicts, deletion, and duplicate bundles.
10. Before release: OS-protect private key and repeat security tests.
