# SideNote Windows v0.5 — Local sync groundwork

## New changes
- Persistent installation ID (`local_device_id`).
- Atomic note upsert/delete paired with append-only local change log in SQLite.
- Deletion tombstones, so future peers can learn that a note was deleted.
- `export_local_changes(afterSeq, limit)` returns bounded sequential log entries for a future authenticated transfer layer.
- Existing notes and floating UI are retained. Existing notes are **not** automatically backfilled into the log: initial pairing must use an authenticated full snapshot followed by changes; this is not implemented yet.

## NOT implemented or verified
- No peer discovery, pairing, TLS/Noise, remote import, conflict merging, Android changes or actual synchronization. Do not use this export surface as an internet API.
- Rust compilation, Windows installer and Windows runtime unverified (Rust SDK unavailable here).

## Future sync safety requirements
- Pairing with mutual device approval and authenticated key exchange.
- Initial snapshot plus monotonically acknowledged changes, with cursor persisted per peer.
- Remote changes must be written transactionally without re-emitting new local changes (echo loop protection).
- Conflict forks preserved instead of last-write-wins data loss.
- Tombstone retention until all paired peers acknowledge or protected snapshot compaction.
- SQLite backup before applying schema/protocol migrations and Android SharedPreferences migration.
- Never assume equal title means equal note; use stable IDs.
