# SideNote Windows v1.3.1 — build-readiness patch

## Changes
1. Moved `sha2` into cross-platform `[dependencies]` (previously accidentally scoped to `[target.cfg(windows).dependencies]`).
2. LAN inbound session exits cleanly after replying to the final empty exchange. Previously the client returned success but the server waited for another page, leading to a timeout/disconnect error in server logs.

## Static verification done
- Cargo TOML parses and sha2 appears in global dependencies.
- Protocol source asserts final-exchange completion after a valid response write.
- ZIP verified after packaging.

## Not tested
- Rust `cargo check`, `cargo test`, native Windows DPAPI and MSI build: Rust toolchain unavailable in this environment.
- React/TypeScript build: dependencies not installed; npm registry access not verified.
- Windows-to-Windows real network sync, 1500-note test, malicious peer handling, reconnect: not executed.

## Security / functional release blockers
- The user-supplied shared LAN key is still reused across devices. Device revocation does not rotate the group secret automatically.
- Fingerprint verification is manual. No nearby discovery, QR/code pairing, or automatic reconnect.
- Synchronization and conflicting notes need real two-device acceptance tests.
- Existing Windows-only source remains experimental.

## Antigravity verification commands (on Windows with Rust + Node installed)
`npm install && npm run build`
`cd src-tauri && cargo check && cargo test`
`cd .. && npm run tauri build`
Then execute the two-device acceptance matrix before release.
